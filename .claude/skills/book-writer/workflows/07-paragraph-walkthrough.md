# Workflow 07: Paragraph Walkthrough Mode (문단 단위 정밀 해부 및 튜닝)

> **Lazy Load Notice**: 이 문서는 특정 절이나 핵심 챕터를 문단 단위로 정밀 해부하는 **`paragraph-walkthrough`** 요청 시에만 로드됩니다.

## 1. 목적 및 설계 원칙 (Why-First)

책의 핵심 개념을 정의하는 하이라이트 구간이나 복잡한 코드가 등장하는 절은 문단 하나의 논리 비약만으로도 독자의 이해도가 급락합니다. 문단별로 **(1) 집필 의도(Why) ➔ (2) 기술/논리 정확성 ➔ (3) 문장 호흡**을 현미경처럼 점검합니다.

## 2. 실행 절차 및 직접 소통 프로토콜

1. **문단별 역할 태깅 (`chapter-writer` - Opus)**
   - 대상 섹션의 각 문단이 수행하는 역할(문제 제기 / 배경 설명 / 코드 제시 / 엣지 케이스 보충 / 요약)을 정리하여 `tech-reviewer`와 `proofreader`에게 `SendMessage`로 공유합니다.
2. **문단별 코드-설명 밀착 검증 (`tech-reviewer` - Opus)**
   - 각 문단 바로 아래의 코드 블록이 실행 가능한지, 문단의 설명 순서와 코드의 실행 흐름이 1:1로 대응하는지 확인하고 어긋난 부분을 `SendMessage`로 지적합니다.
3. **문단 간 전이(Transition) 및 리듬 교정 (`proofreader` - Sonnet)**
   - 앞 문단의 마지막 문장과 뒷 문단의 첫 문장이 자연스럽게 이어지는지, 지시대명사("이것은", "그 결과")가 모호하지 않은지 교정안을 작성하여 `chapter-writer`에게 전달합니다.
4. **즉시 반영 및 검증 (`chapter-writer`)**
   - 문단별 튜닝 결과를 반영하고 전체 단어 수(2,500~4,000 단어)와 메타데이터 주석 무결성을 유지한 채 종료합니다.
