# Workflow 06: Supervised Review Mode (저자 참여형 감독 리뷰 파이프라인)

> **Lazy Load Notice**: 이 문서는 인간 저자(User)가 의사결정에 직접 개입하는 **감독 리뷰(`supervised-review`)** 요청 시에만 로드됩니다.

## 1. 목적 및 설계 원칙 (Why-First)

에이전트들끼리만 합의하여 원고를 고치면 때로는 인간 저자가 의도한 독특한 문체나 파격적인 주장까지 평범하게 다듬어 버리는 부작용(Over-smoothing)이 발생합니다. 따라서 논쟁적인 기술 선택이나 서사 방향성 변경은 에이전트들이 대안을 도출한 뒤 인간 저자의 승인을 받아 반영합니다.

## 2. 실행 절차 및 직접 소통 프로토콜

1. **쟁점 도출 (`tech-reviewer` & `chapter-reviewer` - Opus)**
   - 두 Opus 리뷰어가 원고를 읽고 `SendMessage`로 서로 의견을 교환하여, 단순 오탈자가 아닌 **저자의 판단이 필요한 핵심 쟁점 3~5가지**(예: 아키텍처 대안 A vs B, 독자 난이도 조절, 갈등 구조의 해법 방향)를 추려냅니다.
2. **저자 의사결정 요청 (Human-in-the-Loop Gate)**
   - 각 쟁점별로 **왜(Why) 이 부분이 문제인지**와 선택지별 장단점을 요약하여 사용자에게 제시하고 결정을 기다립니다.
3. **결정 사항 정밀 반영 (`chapter-writer` - Opus)**
   - 사용자의 선택이 내려지면 `chapter-writer`가 해당 지침에 맞춰 원고를 수정하고, 품질 체크리스트(`메타데이터 주석`, `2,500~4,000 단어`, `코드 블록 실행 가능`)를 검증한 뒤 완료합니다.
